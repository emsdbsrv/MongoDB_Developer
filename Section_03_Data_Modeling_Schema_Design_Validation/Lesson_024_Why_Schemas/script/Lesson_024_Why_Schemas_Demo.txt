MongoDB Developer Learning Path — Schema Thinking Demo

Purpose
-------
Show that MongoDB can allow documents in one collection to evolve, while the application still needs an intentional document contract.
The demo uses Order Management only.

Prerequisite
------------
Run from a machine where mongosh can connect to MongoDB.

1) Use the application database
-------------------------------
use orderdb

2) Reset the demo collection
----------------------------
db.orders.drop()

3) Insert representative documents
----------------------------------
db.orders.insertMany([
  {
    orderId: "ORD-1001",
    status: "CONFIRMED",
    totalAmount: 1250.00
  },
  {
    orderId: "ORD-1002",
    status: "PLACED",
    totalAmount: "980.00",
    priority: true
  },
  {
    orderId: "ORD-1003",
    status: "SHIPPED",
    shippingAddress: { city: "Chennai" }
  }
])

4) Inspect the different document shapes
-----------------------------------------
db.orders.find(
  {},
  {
    _id: 0,
    orderId: 1,
    status: 1,
    totalAmount: 1,
    priority: 1,
    shippingAddress: 1
  }
).pretty()

Observation
-----------
The collection accepts documents with different combinations of fields.
That flexibility is useful during application evolution, but the developer must decide which differences are intentional.

5) Inspect the BSON type of a field
----------------------------------
db.orders.aggregate([
  {
    $project: {
      orderId: 1,
      amountType: { $type: "$totalAmount" }
    }
  }
])

Observation
-----------
Two documents can use the same field name with different types.
This is a form of schema drift that the application should detect and resolve deliberately.

6) Inspect optional field presence
---------------------------------
db.orders.aggregate([
  {
    $project: {
      orderId: 1,
      hasPriority: { $ne: ["$priority", null] },
      hasShipping: { $ne: ["$shippingAddress", null] }
    }
  }
])

7) Read the intended Order Management shape
--------------------------------------------
const intendedOrder = {
  orderId: "ORD-2001",
  orderDate: new Date(),
  status: "CONFIRMED",
  items: [
    { productId: "P100", qty: 2, price: 499.50 }
  ],
  shippingAddress: { city: "Chennai", country: "India" },
  payment: { method: "CARD", status: "AUTHORIZED" }
}

intendedOrder

8) Cleanup
----------
db.orders.drop()

Key lesson
----------
Flexible schema means the database can accommodate change.
Schema thinking means the application still defines what the data should mean and how it should be used.
