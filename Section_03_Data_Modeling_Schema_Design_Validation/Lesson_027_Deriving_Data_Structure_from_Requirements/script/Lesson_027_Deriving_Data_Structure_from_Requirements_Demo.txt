MongoDB mongosh demo — Deriving Data Structure from Requirements

Prerequisite
------------
Run from a machine where mongosh can connect to MongoDB.

1) Start with the application requirement
------------------------------------------
# The application needs to:
# - show an order with items, shipping and payment
# - find a customer's orders
# - update order status
# - keep product catalog data independent

2) Use the application database
--------------------------------
use orderdb

3) Reset the topic-specific collections if needed
---------------------------------------------------
db.orders.drop()
db.products.drop()

4) Create one product as independently managed data
----------------------------------------------------
db.products.insertOne({
  sku: "LAP-001",
  name: "Laptop",
  category: "Electronics",
  price: 499.50,
  stock: 100
})

5) Create an order from the requirements
----------------------------------------
db.orders.insertOne({
  orderId: "ORD-1001",
  customerId: "CUST-1001",
  status: "PLACED",
  items: [
    { sku: "LAP-001", qty: 2, unitPrice: 499.50 }
  ],
  shippingAddress: {
    city: "Chennai",
    country: "India"
  },
  payment: {
    method: "CARD",
    status: "AUTHORIZED"
  }
})

6) Access pattern: get an order with its related data
-----------------------------------------------------
db.orders.findOne({ orderId: "ORD-1001" })

7) Access pattern: find all orders for a customer
-------------------------------------------------
db.orders.find({ customerId: "CUST-1001" }).pretty()

8) Access pattern: update the order status
--------------------------------------------
db.orders.updateOne(
  { orderId: "ORD-1001" },
  { $set: { status: "CONFIRMED" } }
)

9) Inspect the derived order document
-------------------------------------
db.orders.findOne({ orderId: "ORD-1001" }).pretty()

10) Review the design decision
------------------------------
print("Embedded: items, shippingAddress and payment because they belong to the order read/write unit.")
print("Reference-style link: customerId and sku connect independent business objects.")
print("Separate collection: product catalog has its own lifecycle and can grow independently.")
print("Design flow: requirements -> access patterns -> document shape -> test the model.")

11) Optional cleanup
--------------------
db.orders.drop()
db.products.drop()
