MongoDB Developer — Structuring Documents

Purpose
-------
Practice structuring a MongoDB order document around a real-world business object.
This demo focuses on document shape: top-level fields, nested objects, arrays of embedded documents, and readable field names.

Prerequisite
------------
Run from a machine where mongosh can connect to your MongoDB instance.

1) Switch to a practice database
---------------------------------
use order_modeling

2) Reset the example collection
--------------------------------
db.orders.drop()

3) Insert one structured order
------------------------------
db.orders.insertOne({
  orderId: "ORD-1001",
  orderDate: new Date(),
  status: "CONFIRMED",
  customer: {
    customerId: "CUST-001",
    segment: "Enterprise"
  },
  items: [
    { productId: "P100", quantity: 2, price: 499.50 },
    { productId: "P200", quantity: 1, price: 25.50 }
  ],
  shippingAddress: {
    city: "Chennai",
    country: "India"
  },
  payment: {
    method: "CARD",
    status: "AUTHORIZED"
  }
})

4) Read the complete document
-----------------------------
db.orders.findOne({ orderId: "ORD-1001" })

5) Insert a second order with the same overall shape
-----------------------------------------------------
db.orders.insertOne({
  orderId: "ORD-1002",
  orderDate: new Date(),
  status: "PLACED",
  customer: {
    customerId: "CUST-002",
    segment: "Standard"
  },
  items: [
    { productId: "P300", quantity: 1, price: 899.00 }
  ],
  shippingAddress: {
    city: "Mumbai",
    country: "India"
  },
  payment: {
    method: "UPI",
    status: "PENDING"
  }
})

6) Inspect only the business fields
------------------------------------
db.orders.find(
  {},
  { _id: 0, orderId: 1, status: 1, customer: 1, items: 1, shippingAddress: 1, payment: 1 }
).pretty()

7) Observe the structure
------------------------
Notice the hierarchy:
order document -> customer / items[] / shippingAddress / payment

Practice
--------
Create one more order that keeps the same business shape but changes the number of items, status, shipping city, and payment method.
Do not introduce abbreviated field names; keep the structure self-describing.
